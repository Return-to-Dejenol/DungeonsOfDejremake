Dejenol Restoration Project

A fan remake of Mordor: The Depths of Dejenol (1995), modernized and written in Rust. It opens on the original's free shareware release (floors 1-3); import your own registered copy for all 15. The remake supplies new code and a rebalance on top.

It started as a fork of matteo-prosperi/DungeonsOfDejremake. That project publishes no source, so all the code here is new. Source: Return-to-Dejenol/DungeonsOfDejremake.

Play

  • WindowsThe installer (36 MB). It offers newer releases itself, or check in Options.
  • AndroidThe APK for Android 8 and up. Allow installs from your browser to open it.
  • In the browserNothing to install. Your files and saves stay in this browser.

Every build starts on the shareware floors. Turn on Cloud Saves in Options to carry your characters between devices with a sync code. All releases.

Design pillars

  • Modern RPG mechanicsModern mechanics come first. Strict faithfulness to 1995 does not.
  • Corpse recoveryWhen a character dies, the body stays in the dungeon for someone to recover.
  • A party of your own charactersYour other characters join the party under AI control.
  • Flatter XP, deeper rewardsLevelling takes far less XP, and deeper floors pay more.
  • Casters get to castCasters get far more SP, and SP potions drop nearly as often as healing potions.
  • Fair boxes earlyMagically locked boxes are rare on floors 1-5 and get more common deeper down.
  • Original art and musicThe original's pictures and sounds, and its MIDI music played through a SoundFont, all read from the game files on your device.
  • Everywhere, in RustWindows, web and Android from one Rust codebase.

The rebalance in numbers

The rebalance is a patch file, patches/modern.toml, applied on top of the imported original tables. Every value is a first-pass placeholder to tune during play-testing. Any other patches/*.toml overrides it key by key.

Tech stack

PieceWhat it does
crates/rulesHeadless game rules: the party, combat, magic, treasure, monsters, the city, party AI macros and the tuning layer. No window, fully testable.
crates/extractImports MORDOR11.ZIP, a .WIP archive, or an install folder, and reads the original's bitmaps.
crates/gameThe egui window: the original's art and music, the city, the dungeon.
patches/TOML rebalance layers, merged key by key.
BuildsA Windows installer (Inno Setup), a static WASM web build (trunk) that keeps files and saves in IndexedDB, and an Android APK for arm64 and x86_64 on Android 8 and up, built without Gradle.
crates/sync-serverddj-sync, the cloud save server: each sync code's save files, never game data.
Toolsddj-save shows and edits saves. scripts/re/ reads the original's rules out of MORDOR.EXE.

It's a single Cargo workspace in Rust. To run from source on the bundled shareware:

cargo run -p ddj-extract -- tests/fixtures/MORDOR11.ZIP
cargo run -p ddj-game

Bring your own data

Apart from the original's freely redistributable shareware release, this repo and its builds contain no original-game content. Every build ships the unmodified shareware MORDOR11.ZIP (floors 1-3), which its own documentation allows, and imports it on first run.

For all 15 floors, you import your own registered copy: a folder, a zip or MORDOR.WIP. The importer extracts the data tables, pictures, MIDI music and sounds, never the program itself. There are no registration codes; the data itself unlocks the full game. In the browser, your files stay in that browser's storage, and the server never holds or sends registered game data.

The remake's changes ship only as patch files that apply on top of those tables.
